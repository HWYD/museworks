# Museworks 工作流等级

## 判级方法

依次检查以下四个维度，并采用命中的最高等级：

1. 边界范围：是否改变共享接口、跨包、跨进程或外部系统契约。
2. 敏感性与权限：是否接触密钥、用户隐私、系统权限或安全控制。
3. 可逆性：失败后能否通过停止进程或还原代码安全恢复。
4. 影响半径：是否影响用户数据、安装环境、发布产物或多个运行组件。

路径只决定领域 Skill，不决定 Change Level。先读取实现、调用方和契约；调查后风险仍不能排除时才采用更高等级。混合改动采用最高等级。项目明确禁止的设计不能通过提高等级获得许可。

## L0：无行为变化

适用于文档、注释、格式、忽略规则和其他不改变可观察行为的维护。直接实施，人工检查内容并运行 `git diff --check`；不要求 TDD、正式任务文档、新 worktree、子代理或独立审查。

## L1：局部且可逆

适用于无共享契约或权限变化的单模块缺陷、局部 UI、纯内部逻辑和开发命令修复。缺陷使用 systematic-debugging，生产行为使用最小 TDD，并运行聚焦验证。默认直接实施，不创建 design、plan、SDD 临时文档或新 worktree，也不要求独立审查。

开发环境中的可执行文件定位属于 L1，除非同时改变打包后的生产进程、权限或安装边界。

## L2：受控的跨边界变化

以下改动至少为 L2：

- 新增或兼容性修改 HTTP、IPC、SSE、Tool、Provider、配置 schema 或跨包类型契约。
- 修改生产环境子进程启动、退出、取消、超时、重试、并发或资源释放。
- 在既有权限范围内增加文件、网络、GPU、ComfyUI 或本地服务访问。
- 修改持久化格式，但不迁移、删除或覆盖既有用户数据。
- 修改缓存、队列或共享状态，并可能影响一致性。
- 收紧权限、安全校验、CSP、IPC allowlist 或输入验证。
- 修改 workspace、Turbo、打包、只读 CI 或普通兼容依赖版本。
- 修改模型推理参数或 ComfyUI Adapter，但不下载、安装或删除模型。

L2 提交一份精简计划，使用隔离 worktree，默认直接实施并执行契约和调用方验证。完成后只进行一次最终独立审查。精简计划包含目标、接口变化、实现分组、测试和假设，不使用完整 SDD 模板，也不生成 task brief 或 task report。

## L3：敏感、不可逆或系统级变化

以下改动强制为 L3：

- Ark API Key、凭据、加密、safeStorage、秘密传输或秘密日志处理。
- 扩大系统权限、文件范围、网络范围或进程执行能力。
- 放宽 Electron sandbox、context isolation、CSP、IPC 或 Renderer 隔离。
- 用户数据迁移、删除、覆盖、不可逆格式转换或破坏性命令。
- 外部遥测、用户数据上传或新增第三方数据接收方。
- 模型、插件、运行时或原生二进制的下载、安装、执行和删除。
- 新增 native dependency、install/postinstall 脚本或供应链执行边界。
- 依赖或工具链主版本升级；普通兼容升级保持 L2。
- 发布、签名、公证、自动更新、生产部署或 CI 写权限与秘密。
- 破坏性公共契约变更，且需要调用方或用户数据协同迁移。

L3 必须先获得用户批准，完成 design 和 implementation plan，使用隔离 worktree 与 subagent-driven-development，执行逐任务和最终独立审查，并记录回滚或恢复方式。`Task N` 保留在 implementation plan；task brief、task report、review package 和 progress ledger 只存在于 Git 忽略的 SDD workspace。

## 用户覆盖

用户可以明确要求更强的计划、隔离或审查。除非用户明确要求，Agent 不得因个人偏好把 L0/L1 升级为完整流程。用户要求不能降低项目安全红线。
