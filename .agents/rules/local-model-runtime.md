# 本地模型运行时规则

## 资源边界

- 开发参考硬件为 RTX 3060 Ti 8GB VRAM（显存）；这是 GPU 显存门禁，不是系统内存规格或性能承诺。
- 默认未来生成基线为 `batch=1`、`768x768`、`preview=none`，并采用动态显存或 CPU offload。
- `1024x1024` 仅可在目标 RTX 3060 Ti 8GB VRAM 实机门禁通过后启用；门禁前不得宣称稳定运行。
- 启动、加载、并发推理和缓存策略必须分别探测 GPU 显存与系统内存；系统内存预算另行记录和验证，不得由 8GB VRAM 推导。
- 当模型、上下文长度、并发数或缓存组合可能超过预算时，应拒绝启动、降级配置或提示用户调整。
- 不假定高于参考设备的 GPU 显存、稳定联网或预先下载的模型文件。

## 运行时契约

- 通过明确的 adapter 封装不同本地模型服务，避免供应商格式泄漏到业务和 UI 层。
- 探测能力、版本、模型清单和健康状态后再发起任务，不硬编码单一端点或模型名称。
- 所有外部响应先校验再转换为内部类型；异常响应不能直接进入界面或持久化层。
- 请求必须设置超时、取消和并发上限，关闭窗口或停止任务时向上游传播取消。

## 流式输出

- 本地模型的流式结果只转换为 SSE 事件契约：增量、完成、错误和取消。
- 不使用 NDJSON、逐行 JSON 或供应商私有字段作为 UI 协议。
- 解析器需要处理断连、半事件、错误事件和完成后的资源释放。

## 用户体验与可观测性

- 模型不可用、GPU 显存不足、系统内存不足或连接失败时，给出明确的中文原因和可执行建议。
- 日志可以记录模型标识、耗时和脱敏后的错误分类，不记录提示词中的敏感内容、密钥或授权头。
- 重试应有次数和退避上限；禁止无限重试导致资源耗尽。

## 测试

- 使用可控模拟运行时验证健康检查、预算拒绝、超时、取消和 SSE 事件映射。
- 测试 fixture 必须小而确定，不能要求下载真实大模型或占满目标 GPU 显存与系统内存。
