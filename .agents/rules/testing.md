# 测试规则

## TDD 与范围

- 任何生产行为的新增、修改或缺陷修复，先写或更新一个会失败的测试，再实现最小改动使其通过。
- 测试应描述用户或调用方可观察到的行为、错误和边界，而非私有实现顺序。
- 缺陷修复优先覆盖最小复现路径，并补充必要的回归边界。
- 纯人工维护的文档、注释或说明文字改动无需添加自动化测试；改为人工检查准确性、链接和示例。

## 隔离

- 测试使用测试专用 fixture、临时目录和依赖注入隔离文件系统、网络、时钟、随机性和模型服务。
- 不得为测试污染生产目录结构、生产导出面、运行时模块路径或 Electron IPC 能力。
- 不得添加仅供测试调用的生产开关、后门 channel 或隐式全局状态。
- 模型或网络集成测试必须可控：使用 mock/server 或明确标记的可选集成环境。

## 流与异步

- SSE 测试覆盖增量、完成、错误、取消和资源释放；不得引入 NDJSON 断言作为替代协议。
- 异步测试必须等待可观察的完成条件，避免固定 sleep 造成不稳定。
- 针对取消和超时的测试应验证上游停止，而不只验证 UI 不再显示。

## 验证

- 优先运行与改动最贴近的单元测试，再按影响范围运行类型检查和 lint。
- 测试失败时保留失败信号并定位根因；禁止删除断言、skip 或吞掉异常来伪造通过。
- 每次交付前执行 `git diff --check`，并如实报告执行的命令及结果。
